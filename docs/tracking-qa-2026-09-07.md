## Confirmed issues and changes

- The prior Google tag loaded on first visit even with analytics storage denied (advanced consent behavior). It now loads only after explicit Analytics consent on clearfin.ca or www.clearfin.ca. Advertising consent alone does not enable Google. Preview/local hosts cannot load the production Google or Meta tags.
- The real Google SDK recorded the initial page but not the tested Next.js navigation. A pathname observer now sends one manual page_view per visited path, using send_page_view:false for configuration. Repeating preferences or changing only comparison query parameters does not add a view. **Keep GA Enhanced Measurement history-based page views off**: Google documents that send_page_view:false alone does not disable that account setting. Future account changes require re-running duplication checks.
- Revocation sets Google's documented ga-disable flag and removes _ga/_ga_* first-party cookies. We do not send a denied-state update to an already loaded SDK, avoiding advanced-consent pings. Previously queued provider batches can still finish: revocation cannot retract already authorized/queued data. Browser checks drain prior batches before testing new post-revocation navigation. Meta retains its separate consent, manual events and cookie removal.
- Google page_location and page_referrer omit query strings and fragments. Bounded plain campaign labels from six standard utm_* fields map to explicit campaign fields; arbitrary queries, email-shaped/unsupported/overlong labels are not forwarded by this code. Campaign labels must never contain personal data. This is not a general detector for personal information hidden in otherwise valid campaign labels. Query-only virtual views and arbitrary attribution parameters are not collected by the manual page-view implementation.
- All four Apply handlers share one helper. Meta ApplyClick requires Advertising consent; first-party card-click counting requires Analytics consent. The latter sends only cardId, omits credentials/referrer, uses keepalive and a five-second timeout, and never awaits tracking before opening the application link. An outbound click remains intent, not an application, approval or commission.
- The click API rejects missing consent assertion (403), malformed/extra-field/invalid-ID bodies (400), and bodies over 1,024 characters (413). Storage misconfiguration returns 503; storage exceptions/errors return 500; only a successful insert returns ok:true. It no longer disguises failures as success. ID syntax is validated, not live catalogue membership. The client consent header is an assertion, not authentication or abuse protection; body size is checked after reading, not a streaming request-memory limit.
- Fixed server diagnostic labels distinguish storage_unconfigured and storage_failed; raw request/database error payloads and secrets are not logged. Browser warnings and clearfin-tracking-diagnostic events expose only channel/reason for script-load and click-delivery failures. No new remote diagnostic collector is introduced. Actual Google/Meta endpoint receipt cannot be inferred from a script load or an event queue.
- The privacy page now describes the implemented Google loading/withdrawal behavior. Card economics, SEO URLs, artwork, visual design, chat and waitlist policies remain unchanged.

## Verification and safe reproduction

- All 32 tests in npm run test:qa pass, including consent/Meta, existing reliability tests and new Google/click tests. Covers missing/denied/granted consent, blocked storage/SDK, revoke during download, regrant, cross-tab changes, production host restrictions, route de-duplication, query stripping/campaign allowlist, API validation/configuration/storage outcomes and minimal client requests. Focused ESLint, TypeScript and production build pass (162 routes; local static catalogue fallback).
- npm run test:qa:tracking uses isolated installed Chrome with real provider SDKs and a normal Chrome user-agent string (Meta suppressed requests under the default headless user-agent). For local QA, production-host GET requests are proxied to a local production-mode server on port 3100, with no production-host override shipped in the application. Provider measurements and all site writes from page interactions are intercepted; outbound applications are replaced by inert pages. This validates SDK request generation, not dashboard ingestion.
- Browser coverage: four consent combinations, first visit and Reject, initial/SPA page views, Compare/Calculator/Top Picks/card-detail Apply links, calculator completion, private-answer exclusion, cookie removal, revocation and blocked-script diagnostics. Empty-body handler probes separately verify 403/400 without supplying a card that could be stored. No real leads, chat requests, applications or click records are created.
- Use PLAYWRIGHT_MODULE for an existing Playwright installation and QA_BROWSER_CHANNEL=chrome. QA_BASE_URL defaults to http://127.0.0.1:3100; the verified public-site value is https://www.clearfin.ca. Do not point this test at unrelated sites. SDK loading needs network access; measurement interception must remain enabled.
- Final test counts and preview/production evidence are recorded in the batch pull request after release.
